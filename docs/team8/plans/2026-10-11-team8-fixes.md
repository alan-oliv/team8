# team8 fixes Implementation Plan

> **For agentic workers:** this plan is executed by teammates that `team8:run` dispatches from the shared task list. Read your own task section. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Land the fixes from the 2026-10-11 design: one task gate, owners on every task, message delivery to busy teammates, a quiet SessionStart with a resume hint, report and git rules, a smaller setup, and current model prices.

**Architecture:** Every fix stays on classic command hooks, skill and agent prose, the console's setup and its price catalog; nothing needs a mod. The `delivery` branch merges first and alone, then three tracks run in parallel on disjoint files: hooks and server, skills and agent files, and the price catalog.

**Tech Stack:** POSIX sh + jq hook scripts, TypeScript (Node 22, vitest, tsc), Markdown skills and agent definitions, Claude Code 2.1.296.

**Spec:** `docs/team8/specs/2026-10-11-team8-fixes-design.md`

## Global Constraints

- The branch `fixes` is already checked out and shared. Never create, switch or check out a branch.
- Commit by pathspec: `git add <your new or deleted paths>`, then `git commit -m "…" -- <your paths>`, message first. Never a bare `git commit`, `git add -A` or `git add .`. The only exception is Task 1's merge commit, which runs while no other track is live.
- Never `git stash`: the working tree is shared.
- Never commit `plugin/dist`; the bump workflow builds it. Do not run `npm run build`. A build check bundles to `$TMPDIR`.
- Tests: `npx vitest run <files>`; typecheck: `npx tsc --noEmit`. Run only the tests covering your files; the lead runs the full suite at close.
- Hook scripts are POSIX `sh` with `set -u`, read their payload from stdin, treat `jq` as optional, exit 0 on anything they cannot read, and are executable (`chmod +x`).
- Comments say why, never what; match the surrounding file's style and density.
- Commit messages are one plain imperative sentence in this repo's style ("Add the team8 fixes design"). No AI attribution or "generated with" footer.
- Claude Code 2.1.296 facts this plan relies on (the spec's Probes): the `Agent` tool's `effort` never reaches a named teammate; a busy in-process teammate gets no message until its turn ends; an in-process teammate claims the first pending, unowned, unblocked task at spawn and when idle; a plugin's own `settings.json` accepts only `agent` and `subagentStatusLine`.

Create `plugin/bin/task-gate.sh`:

```sh
#!/bin/sh
# PreToolUse gate on TaskCreate and TaskUpdate. It reads only the call's own
# input, never a task file, so it cannot read the wrong list and it leaves
# other sessions' task lists alone:
# - a TaskCreate carrying any of team8's four metadata keys must carry all
#   four; one carrying none of them is not team8's (a todo list, a checklist);
# - a teammate's TaskUpdate to completed must carry metadata.verified in that
#   same call; the lead's own completions carry no agent_id and pass.
#
# CONTRACT: exit 2 blocks the call and returns stderr to the model as the
# reason, exit 0 allows it. A broken gate must never block work, so anything
# short of a clean read falls through to exit 0.
set -u

payload=$(cat 2>/dev/null) || exit 0
[ -n "$payload" ] || exit 0

command -v jq >/dev/null 2>&1 || exit 0

reason=$(printf '%s' "$payload" | jq -r '
  (.tool_input // {}) as $in
  | ($in.metadata // {}) as $m
  | if .tool_name == "TaskCreate" then
      ["complexity", "model", "effort", "why"] as $keys
      | [$keys[] | select((($m[.] // "") | tostring) == "")] as $missing
      | if ($missing | length) > 0 and ($missing | length) < ($keys | length)
        then "TaskCreate: metadata is missing \($missing | join(", ")) — a team8 task carries complexity, model, effort and why (team8:tasks)"
        else empty end
    elif .tool_name == "TaskUpdate" and $in.status == "completed"
      and (.agent_id // "") != ""
      and ((($m.verified // "") | tostring) == "") then
      "task #\($in.taskId): put metadata.verified \"<command> → <result>\" in the same TaskUpdate that sets status completed"
    else empty end
' 2>/dev/null) || exit 0

[ -n "$reason" ] || exit 0
echo "$reason" >&2
exit 2
```

```ts
/**
 * The tier one request is billed at. claude-haiku-5-5 has two rate cards: its
 * long-prompt card applies once a request's prompt (input plus cache reads and
 * writes) is over 100K tokens. Every other model has one.
 */
export function pricingFor(raw: string | undefined, promptTokens: number): PricingTier {
  const resolved = resolveModel(raw);
  const long = catalog.models[resolved.canonical]?.longPrompt;
  return long && promptTokens > long.over ? long.pricing : resolved.pricing;
}
```

export function totalCost(records: UsageRecord[]): number {
  let sum = 0;
  for (const record of dedupeUsage(records)) {
    sum += costOf(record.usage, pricingFor(record.model, promptTokensOf(record.usage)));
  }
  return sum;
}

function promptTokensOf(usage: Usage): number {
